# Koog 추상 검증과 후속 계획

기준일: 2026-09-04. 최상위 기준은 [설계 선언](../AHP_CHARTER.md)이다. Koog 검증의 단계 1–5에 이어 새 Port 선언과 세 adapter 연결·native 기본 검증도 수행했다. 이 문서는 이전 실험의 범위와 현재 남은 검증을 구별하며, 최신 실행 결과는 [native 검증 기록](native-port-validation.md)에 있다.

## 목적

구현 방식이 다른 하네스에서 비즈니스의 같은 목적을 수행하여 추상의 타당성을 검증한다. 기존 API를 유지하는 것 자체가 성공 조건이 아니다. 구현 가능성, 기본 계약의 정당성, 선택 보장의 필요성을 구별하고 잘못 묶인 책임은 분리·제거한다.

Koog 하나를 이질적인 비교 대상으로 사용했다. 로컬 graph runtime 검증을 클라우드 단절·원격 재접속·모든 하네스의 보편적 호환성 증명으로 일반화하지 않는다.

## 업무 시나리오와 새 계약의 판정 기준

합성 업무 요청과 참고 자료를 검토하여 처리안을 만들고, 필요한 판단을 받아 모의 상태를 변경한다. 업무 규칙과 수용 조건은 소비 애플리케이션이 소유한다. tool을 등록하는 방식은 adapter 구성에 둔다.

| 시나리오 | 업무 목적 | 개정 계약에서 확인할 보장 |
|---|---|---|
| S1 검토·결과 | 자료를 조회하고 처리안·근거를 받음 | 여러 내부 호출을 포함한 한 Task, outcome/output 분리, observer 독립성, 구조화 요구의 실제 보장 |
| S2 승인·질문 | 변경을 판단하거나 빠진 정보를 제공 | 승인 전 효과 없음, 거절·typed 답변·대기·일회 응답·취소의 의미 |
| S3 연속성·영속성 | 이전 검토에 조건을 추가하고 이어감 | 기본 문맥 연속성과 선택 영속 보관 구별, release/재생성 뒤 약속한 reopen, checkpoint 복원과 구별 |
| S4 취소·종결 | 중단 요청 후 다음 행동을 결정 | 요청과 실제 종료 구별, 완료 경쟁, bounded cleanup, Unresolved와 이후 효과 가능성 |

## 단계 1 — 기준선과 환경: 수행 완료

AHP 0.1.0 revision, 실제 Koog 1.2.0 artifact, Kotlin/JDK/의존성을 기록하고 실험을 독립 build로 격리했다. 모델 경계는 통제된 응답으로 대체하고 업무 자료·변경은 fixture로 제한했다. 실모델 인증이 준비되지 않은 범위는 미수행으로 기록했다.

## 단계 2 — Native Koog: 수행 완료

AHP 밖에서 graph·tool registry·event hooks로 조회·결과·취소를 수행했다. 동일 native session의 반복 입력과 파일 checkpoint 복원을 실제 관찰했다. 처음부터 AHP의 영속 Session을 맞추기 위한 저장소를 native 기능인 것처럼 추가하지 않았다.

## 단계 3 — 기존 Port 연결: 수행 완료

당시 공개 AHP 소스를 바꾸지 않고 부분 Koog adapter를 연결했다. 이 단계는 기존 계약의 대응 가능성을 보는 실험이었다. 완료 이력 저장·승인 중재·관찰 전달은 adapter가 보충한 책임으로 기록했다.

당시 구현을 새 AgentTask 계약의 구현이라고 부르지 않는다. runtime·tool 실행은 실제였지만 모델은 fixture였으며 완전한 적합성 검증은 아니었다.

## 단계 4 — 행동·효과 대조: 수행 완료

S1–S4를 공개 Port 관찰과 모의 도구의 실제 실행 기록으로 대조했다. 없는/늦은/느린 observer, 승인 대기, 취소, 문맥 보관과 비협조적 작업의 종료 유예 초과를 재현했다.

기존 Codex/Gemini는 기존 회귀 suite를 재실행했다. 두 실제 provider에 동일 업무 기능을 연결한 검증이나 새 공통 계약 검증을 수행했다고 보고하지 않는다.

## 단계 5 — 추상 판정: 수행 완료, 설계 기준 갱신

실험 사실을 바탕으로 [추상과 용어](abstraction-and-terminology.md)를 정했다. 기본 영속 Session, 승인 전용 interaction, 강제 취소 확정, core 원본 trace, bridge 필수 검사 등의 전제를 바로잡는다. 기존 시그니처를 지킬 수 있다는 이유로 새 추상을 제한하지 않는다.

## 증거 수준

- 문서/API 조사: 가능성과 제약을 확인했으나 실제 실행 증거는 아니다.
- 결정적 재현: 실제 Koog runtime에 통제된 모델 응답·모의 업무 기능을 연결했다.
- 실모델 통합: 실제 SDK/runtime/model까지 연결한 증거다. 이번 Koog 실험에서는 수행하지 않았다.

당시 소스는 Git 이력에, 측정 결과는 기존 evidence JSON에 보존한다. 실행 가능한 실험 코드는 현재 Port로 이전했으며 새 결과를 [별도 기록](../experiments/koog-validation/evidence/current-port-migration.json)에 남긴다. 과거 결과를 현재 실행의 통과 수로 재사용하지 않는다.

## 추상 변경의 증명 책임

기존 추상을 바꾸거나 유지하는 결정 모두 목적과 필요한 보장, 실제 관찰, adapter 보완의 정당성, 필수·선택의 근거, 소비자 영향으로 설명한다. Koog의 편의만으로 새 core를 만들거나 어느 SDK에서 지원하지 않는다는 이유만으로 목적을 제거하지 않는다.

지원 불가·미검증·계약 위반을 구별한다. 모든 작업을 거절하는 adapter를 공통 성공으로 세지 않는다. 현재 선언된 구조화 출력·작업 자원 요구와 미지원 구현을 구별하며, 추가 실증 없는 범용 자원 모델이나 지원 보장을 만들지 않는다.

## 통합 완료 범위와 남은 검증

새 Port·KDoc, 세 adapter·factory·bundle 연결, 소비 예제의 source 컴파일은 완료했다. 공통 7개 시나리오를 세 runtime에 적용한 21개와 구현별 4개가 통과했다. 임시 참조 하네스는 제거했으며 추가 검증은 실제 제공 경계를 사용한다. 상세 상태는 [Port revision plan](port-revision-plan.md)을 따른다.

남은 작업은 시작·응답 수락 확인 유실, 승인 범위와 실제 효과, 사용량·observer 유실, 자원·권한 집행, 영속 문맥 경쟁·복구 등의 조건을 검사하는 것이다. 기존 시나리오 정의의 고정 profile 가정을 바로잡아 재사용하고 선택 기능은 지원한 의미와 사전 거절을 각각 검증한다. 실모델 연동과 artifact 발행도 별도 범위로 남아 있다.

필수 계약은 세 adapter 모두 실제로 충족해야 한다. 일부 실연동 환경이 없으면 통합은 부분 완료이며, fixture 통과로 실연동을 대체했다고 보고하지 않는다. 배포·발행은 별도 실행 작업이다.
