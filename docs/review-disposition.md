# 외부 총평 반영 기록

검토일: 2026-09-04. 대상은 문서 개편 커밋 `7a26361`에 대한 외부 총평과 그 후의 사용자 논의다. [설계 선언](../AHP_CHARTER.md)을 기준으로 문제 제기와 제안된 해법을 분리해 판단했다. 이 문서는 결정 근거이며 행동 규범의 원본은 [규범 위치표](semantic-contract.md#규범의-위치)를 따른다.

## 설계 지적의 처리

| 총평 항목 | 판단 | 반영 / 남긴 이유 |
|---|---|---|
| 1. 종결의 ‘확인’ 미정의 | 문제 수용, 해법 수정 | Task 식별·위임 범위와 증거 의미를 연결하는 조건을 Lifecycle에 정의. 충분한 근거 사용 의무와 provider별 검증 표 추가 |
| 2. 미확정 session의 차단·탈출구 | 문제 수용, 위험 승인 연산 보류 | 기본 조정은 소유 harness의 같은 문맥. 영속성은 선언한 재개·조정 범위에서 차단을 유지하거나 복구를 입증. handle 해제·새 문맥·기존 문맥 복구를 구별 |
| 3. Unresolved 남용 | 수용 | 확인된 결과를 Unresolved로 낮추는 adapter도 부적합. 거짓 취소와 반대 방향의 적합성 시나리오 추가 |
| 4. 연속성 필수·영속성 선택의 근거 | 설명 부족 수용, 구현 가능성 기준 기각 | provider별 이력 처리를 소비자에게 맡기지 않는 연속 위임과, 수명을 넘는 보관·재개의 독립된 목적을 명시 |
| 5. 지원 탐색 | 수용 | 구성·session·환경 scope와 조건, 요구별 validate, 실제 호출 수락을 구별. 조회 없이 필수 요구 전달 가능, unknown과 실행 경계 거절 정의 |
| 6. 보유 이벤트의 목적 심사 | 수용, 일괄 선택화는 기각 | ContextManaged는 선택 진단으로 이동. ReasoningDelta의 공개 설명은 Message의 역할·phase로 통합. 다른 의미 이벤트도 소비 목적 명시 |
| 7. 부분 산출물 | 수용 | 모든 outcome에서 확보한 업무 산출물·사용량을 회수. observer와 독립, 부분·unknown·검증 상태 보존. 필드 배치만 후속 결정 |

종결 근거를 stream·coroutine·process 같은 구현 수단 목록으로 고정하지 않는다. 정상 stream 종료도 관찰 종료일 수 있고, process 종료도 실행이 완전히 귀속돼 있으면 종료 사실의 근거가 될 수 있다. provider terminal 역시 AHP Task와 범위가 맞아야 한다. 구체적인 매핑은 기존 조사·실험 수준과 새 구현 검증을 구별한다.

`discard(acknowledgeUnresolvedRisk)`는 현재 채택하지 않는다. 사용 종료와 같은 문맥의 강제 재사용은 다른 목적이며, 동의 값만으로 문맥 충돌을 방지할 수 없다. 복구를 지원하지 않아도 handle을 정리하고 독립된 문맥에서 새로 시작할 수 있다. 위험을 감수하는 같은 문맥 재사용은 별도 소비 요구·약화되는 보장·실증이 있을 때 다시 판단한다.

연속성의 필수성은 ‘메모리로 모든 하네스가 구현할 수 있다’는 주장에 의존하지 않는다. 구현 가능성은 실현성의 증거이며 기본 책임을 정당화하는 업무 목적을 대신하지 못한다.

이벤트가 모든 Task에서 발생하지 않는 것과 선택 계약인 것은 다르다. 공개 설명은 진행 메시지 표시라는 목적을 갖지만 별도의 추론 이벤트가 필요한 근거는 부족하다. 내용을 버리는 대신 메시지로 통합하고 역할·phase를 보존한다. ContextManaged는 현재 근거로 별도 소비 보장을 식별하지 못했으므로 기본 이벤트에서 제거한다. 단순히 ‘선택적이면 삭제’라는 규칙을 채택한 것은 아니다.

## 정합성·편집 지적의 처리

| 총평 항목 | 판단 / 처리 |
|---|---|
| 8. 금지문 위주 | 문장 수를 기준으로 판단하지 않음. 종결 증거·상관관계·검증 수락에 관찰 조건과 긍정 의무 추가 |
| 9. 규칙 중복 | 원본 위치를 지정하고 종결 정리·실패 분류의 중복 설명을 링크로 줄임. 테스트 기대값·당시 회귀 증거의 요약은 역할이 달라 유지 |
| 10. 제공 경계 | 책임 경계와 ID namespace를 분리. 기본 SessionId는 발급 harness 범위, 영속 참조는 저장 namespace 포함. 계약 문제로 처리 |
| 11. reopenSession 소속 | 영속성 선택 계약의 연산임을 별도 절로 명시. 구체적인 Kotlin interface는 후속 결정 |
| 12. 이름 정책 | 유지·이동·통합 대상을 전환표에 기록. Task 전체와 하위 메시지·도구의 주어에 따라 명명, 일괄 Task 접두어는 채택하지 않음. ToolCallChanged 유지 결정은 이미 있었음 |
| 13. 정리 유예 공개 | 유예와 전체 정리 상한·적용 범위·설정의 사전 문서화 또는 조회 의무 추가. 다중 자원 합산도 명시 |
| 14. reference에 시그니처 없음 | 파일명 유지. 첫 문단에서 개정 의미 계약과 미확정 API를 구별하며 미완성 시그니처를 현재 API처럼 제시하지 않음 |
| 15. decisions 하위 폴더 | 보류. README의 읽는 순서와 규범 위치표로 탐색성을 보완. 파일 이동은 현재 계약 수정의 필수 조건이 아님 |
| 16. artifact 출처 | publishToMavenLocal로 설치한 로컬 artifact 소비 예임을 명시. 공개 저장소 배포를 주장하지 않음 |
| 17. 남은 절 번호 | Koog 계획의 마지막 절 번호 제거 |

## 실험 근거와 Git 상태

검토 시작 시 `7a26361`은 실험을 링크하지만 `experiments/koog-validation`의 재현 파일 13개는 untracked였다. 로컬 링크 검사만으로 커밋의 증거 전달을 검증할 수 없다는 지적을 수용했다. 소스·빌드 설정·lockfile·README·검증 JSON 13개를 명시적으로 Git index에 추가했고, build·캐시 산출물은 제외했다. 실험 내용과 기존 검증 JSON은 새 API에 맞춰 소급 변경하지 않았다.

기존 AGENTS.md는 사용자가 제공한 지침 파일로 남긴다. 내용이 짧다는 이유로 삭제하거나 지침을 만들어 넣지 않는다. `temp` 메시지 수정과 이전 커밋 amend는 이번 처리에 포함하지 않는다. index 추가는 새 커밋 생성과 다르며 기존 HEAD만 받은 clone에는 이 변경이 아직 없다.

## 반영 후 재검토에서 닫은 항목

같은 총평자의 재검토에서 위 반영이 남긴 함의 일곱 개를 확인해 정리했다. 새로운 설계 선택이 아니라 이미 확정한 규범의 결과를 명시한 것이며, 보류 결정을 되돌린 항목은 없다.

| 항목 | 닫은 내용 | 원본 |
|---|---|---|
| 정상 종료의 판정 | 계약이 정의한 종료 보고이고 범위가 Task와 연결되면 충분한 근거다. 범위 검증이 남았다는 이유로 정상 경로를 `Unresolved`로 낮추지 않고, 미확인 범위는 지원 정보와 매핑에 남긴다 | [Lifecycle](lifecycle-and-concurrency.md#종결-확인의-근거) |
| 정리 예산의 배분 | 종결 보고가 임박했다는 근거가 있으면 공개한 상한 안에서 확인을 먼저 수행한다. 확인할 수 있는데 조기 종결로 결과를 잃으면 근거 사용 의무 위반이다 | 같은 절 |
| 차단 기록의 수명 | harness 수명 또는 지원하는 확인·복구까지 유지한다. 기본 계약은 무기한 누적을 요구하지 않으며 수명을 넘는 조정은 영속성 계약이 선언한다 | [문맥 차단과 복구 범위](lifecycle-and-concurrency.md#문맥-차단과-복구-범위) |
| 새 문맥으로의 이동 | 이어갈 내용은 호출자가 새 작업의 입력으로 다시 제공한다. 문맥 복사 기능을 새로 만들지 않는다 | 같은 절의 목적 표 |
| `Warning`의 목적 | 요구가 유지된 상태에서 구성·사용 방식을 고칠 수 있는 사실을 전달한다고 목적을 긍정형으로 정의했다. 부정형 정의만으로는 다른 이벤트에 적용한 심사 기준을 통과하지 못한다 | [이벤트를 남기는 목적](event-contract.md#이벤트를-남기는-목적) |
| `TaskStarted`의 대응 | 시작 이벤트에는 대응 outcome이 없으므로 종결 네 이벤트와 행을 분리했다 | 같은 표 |
| 제거된 이벤트의 잔재 | 사용량 절에 남아 있던 문맥 관리 관찰 서술을 선택 진단 기준으로 고쳤다 | [산출물과 부가 관찰](protocol-reference.md#산출물과-부가-관찰) |

첫 두 항목은 편집이 아니라 새 실패 모드를 막는 계약 문장이다. 근거의 범위를 아직 확인하지 못한 adapter가 정상 완료까지 `Unresolved`로 반환하면 `Completed`가 도달 불가능해지고, 이는 위 3번에서 막으려던 실패와 같다. 확정 이후에는 판정을 바꾸지 않으므로 확인에 쓸 시간의 배분도 판정의 일부로 다룬다.

## 검증과 후속 작업

이번 변경은 README·docs의 규범과 계획에 한정한다. 기존 실험 파일은 보존한 채 Git 누락만 정리한다. 코드·KDoc의 동작 변경, 새로운 공개 타입, 세 adapter 전환, 배포·발행은 수행하지 않는다.

문서의 로컬 링크 146개·절 anchor 24개·코드 fence와 staged diff 공백 검사를 통과했다. 재검토에서 닫은 항목을 반영한 뒤 같은 검사를 다시 수행했다. 로컬 링크 대상은 Git index에도 포함돼 있으며, 실험 재현 파일 13개 등록과 기존 기록의 소스·빌드 SHA-256 11개 일치를 확인했다. 기존 tracked 구현·KDoc의 변경은 없다. 직전 [회귀 검토](regression-review.md)의 기존 Kotlin 71개·Koog 18개 통과는 그때의 실행 기록이며 이번 새 시나리오의 통과가 아니다. 이번에는 런타임 테스트를 재실행하지 않았다.

구현 전에 구체화·실증할 항목은 [전환 계획](port-revision-plan.md#1-확정할-공개-모델)에 남긴다. 특히 adapter별 종결 증거, 영속 조정 범위·복구 수단, 지원 조회와 요구 수락의 공개 타입, 모든 outcome의 데이터 회수와 메시지 변환은 새 코드와 함께 검증해야 한다. 총평의 3번도 테스트 구현이 필요하고, 6번은 실제 이벤트 모델 개정이며, 10·13번은 단순 편집이 아니라 소비자가 의존하는 계약이다.
